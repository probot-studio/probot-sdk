# P15: DRV8317H three-phase BLDC driver (gap G6, option 1)

**Status: hardware-unverified.** Written from the TI datasheet and the Boardoza user guide and
library; not run on a board or a motor. Host tests cover the commutation logic against the HAL
sim only; run on 2026-10-22 (`bd0d149`, `tools/build/build.sh host all header_check --test`), `[drv8317h]` passes 58 assertions in 3 test cases.

The DRV8317H has no commutation logic of its own: it is three half-bridges with fixed dead
time. A BLDC motor turns only if the MCU switches the phases on every Hall edge, within
microseconds. The robot loop (and any thread) is far too slow for that, and WPILib has no
interrupt HAL. Gap G6 option 1 (the lead's choice) adds a small prosdk HAL extension that does
sensored six-step (trapezoidal) commutation in a GPIO interrupt, and a user class on top.

|---|---|---|
| Boardoza DRV8317H breakout (B-DRV8317-BRK, Ozdisan 1473938) | TI DRV8317H (hardware variant, no SPI) | `prosdk::DRV8317H` |

Datasheet: TI SLVSGT3 (December 2022). Section numbers below refer to it.

## Wiring

The board's MCU header pinout follows a TI LaunchPad. Use any free GPIOs (0-48):

| Board pin | Signal | To |
|---|---|---|
| J4-1, J4-3 | INHA, INLA | `Pins::inhA`, `Pins::inlA` |
| J4-5, J4-7 | INHB, INLB | `Pins::inhB`, `Pins::inlB` |
| J4-9, J4-11 | INHC, INLC | `Pins::inhC`, `Pins::inlC` |
| J4-13, J4-15, J4-17 | HALLA, HALLB, HALLC | `Pins::hallA`, `hallB`, `hallC` |
| J3-17 | nSLEEP (active low) | `Pins::nSleep`, or -1 if tied high some other way |
| J3-19 | nFAULT (open drain) | `Pins::nFault`, or -1 |
| J4-2, J3-4 | AGND | robot GND |

J3-9 and J3-15 also carry nSLEEP and nFAULT ("for internal use only" in the user guide); leave
them unconnected. Motor phases go to OUTA/OUTB/OUTC (J6), the Hall sensors to J7 (5-pin), motor
power to J5 (VBAT, PGND), 4.5-20 V (section 7.3).

Jumpers:

- **J10 (MODE) must be in "3x PWM mode"** (the board default). The driver uses the 3x PWM truth
  table (Table 8-4: INLx = 0 is Hi-Z, INLx = 1 makes OUTx follow INHx). MODE is latched at power
  up (section 8.3.2): move the jumper only with the board unpowered. The "6x direct" and "3x
  direct" positions of the user guide do not exist on the H variant (Table 8-2: not available).
  In 6x mode (Table 8-3) this driver's outputs give no torque: a PWM phase has INH = INL = 1,
  which is Hi-Z in 6x mode, and no input pattern it produces turns on both FETs of one phase.
- J8 (GAIN) and J9 (SLEW): the defaults (1 V/A, 125 V/us) are fine; the driver does not read the
  current sense outputs.

Voltage hazards (ESP32-S3 GPIOs tolerate 3.6 V at most):

- **Hall power (J2).** In the "3V3" position the Halls run from the board's 3.3 V. In the "Ext"
  position they run from the HALL PWR test point; if that is 5 V, open-drain Hall sensors pulled
  up to it put about 5 V on HALLA-C, which damages the ESP32. Use 3V3, or a level shifter. Where
  the Hall lines are pulled up on the board was not traced in the schematic (unverified); the
  ESP32 enables its own pull-ups on the Hall pins.
- **J3-2 is a 5 V input** ("5 V Boost from LaunchPad"). With J1 in the "5 V" position it feeds
  VIN_AVDD (4.5 V minimum, section 7.3). Never connect it to an ESP32 GPIO; with J1 on "VM" it
  can stay open.
- **VSENA/B/C, VSENVM, ISENA-C, C_TAP (J3)** are not used. The VSEN divider ratios were not
  traced (unverified), so do not wire them to an ADC pin before checking that they stay under
  3.3 V at the highest VM.
- Logic inputs: INHx/INLx high is 1.5-3.6 V, nSLEEP 1.7-5.5 V (section 7.5): 3.3 V GPIOs are
  fine. nFAULT is pulled up to AVDD, the chip's 3.3 V LDO (3.15-3.45 V, section 7.5): safe for a
  GPIO input.

## Class API

```cpp
struct DRV8317H::Pins { int inhA, inhB, inhC, inlA, inlB, inlC, hallA, hallB, hallC,
                        nSleep = -1, nFault = -1; };   // all default -1
explicit DRV8317H(const Pins& pins);
void SetThrottle(double throttle);      // -1..1, clamped, NaN is 0; feeds MotorSafety
double GetThrottle() const;
void SetInverted(bool);  bool GetInverted() const;
void Disable();                         // coast until the next SetThrottle
void SetBrakeMode(bool brake);  bool GetBrakeMode() const;   // at throttle 0
bool SetCommutationTable(const CommutationTable& table);     // false if not six distinct pairs
bool IsFault() const;                   // nFAULT low; false without the pin
void SetPolePairs(int);  int GetPolePairs() const;
int GetHallState() const;               // A | B << 1 | C << 2
units::turn_t GetPosition() const;      // Hall steps / (6 x pole pairs)
units::revolutions_per_minute_t GetRpm() const;
void StopMotor();  std::string GetDescription() const;       // MotorSafety
```

`DRV8317H` is a `MotorController`, `MotorSafety` and `TelemetryLoggable` ("Value", "RPM"). Its
sim device is `DRV8317H[<inhA>]` with the output `Throttle` (after inversion), like the other
motor drivers.

Behaviour:

- A non-zero throttle drives the phase pair the table gives for the current Hall state: one phase
  gets the PWM on INHx (high side for the duty, low side for the rest, dead time inside the
  chip), one has its low side on, one floats. A negative throttle swaps the two. The duty is
  |throttle|, at most (period - 1) / period.
- Throttle 0 brakes (default; all three low sides on) or coasts (`SetBrakeMode(false)`; all
  Hi-Z). `Disable()` and `StopMotor()` coast.
- Hall states the table does not drive (0 and 7 with the default table; 7 is also what
  disconnected sensors read with the pull-ups) coast the motor.
- Speed: rpm = 60 / (6 x pole pairs x t), where t is the longer of the last step period and the
  time since the last step. It decays when the steps stop, and is 0 after 0.5 s without a step.
  The sign is the direction a positive throttle drives (negated by `SetInverted`), provided the
  table matches the motor. A Hall jump of 3 steps (ambiguous) is not counted.
- `IsFault()`: the DRV8317H reports VM undervoltage, overcurrent, overvoltage and
  overtemperature on nFAULT and retries on its own after a fixed 5 ms (sections 8.3.11.1,
  8.3.11.3, 8.3.11.4, 8.3.11.7). There is nothing to clear. nFAULT is also low while the chip
  wakes up (at most tWAKE, 3 ms, after the constructor; section 8.4.1.1).
- The constructor drives nSLEEP high; the outputs follow the inputs after tWAKE, 1-3 ms
  (section 7.5). It throws `RuntimeError` when a pin is invalid, given twice or in use, or no
  motor slot or MCPWM timer is left. After an emergency stop it only reports a warning
  (`HAL_INCOMPATIBLE_STATE`) and the motor stays dead.

Defaults: 20 kHz PWM (`kDefaultPwmRate`; the chip accepts up to 200 kHz, section 1; the HAL
allows 1-100 kHz), brake at 0, 1 pole pair, table `platform::hal::kDefaultSixStepTable`.

### Commutation table

`CommutationTable` (= `platform::hal::SixStepTable`) is indexed by the Hall state
A | B << 1 | C << 2 and gives `{high, low}` phases (0 = A, 1 = B, 2 = C) for the forward
direction; `{-1, -1}` marks an invalid state. It must drive exactly six states with six
different pairs, so 60-degree sensor tables are accepted too. The default is the Boardoza DRV8317
Arduino library's table for 120-degree sensors:

| Hall state | 1 | 3 | 2 | 6 | 4 | 5 |
|---|---|---|---|---|---|---|
| Drive | C+ A- | C+ B- | A+ B- | A+ C- | B+ C- | B+ A- |

The right table depends on the motor's Hall and winding order. If the motor stalls, buzzes or
draws high current at low throttle, the table is wrong for it: try swapping two phase wires or
the Hall wires, or pass a different table.

## ESP32-S3 implementation

- **PWM:** per motor one MCPWM timer (10 MHz, up counting; 500 ticks at 20 kHz) with one
  operator, comparator and generator. The generator is created on INHA; its GPIO-matrix output
  selection is read back and INHA returned to the plain GPIO output. The interrupt then routes
  that one PWM signal to the INHx of the switching phase and holds the other INHx pins low. In
  3x mode only one phase switches per step, so one generator is enough. LEDC was not used: its
  6 channels and its one shared rate belong to the digital PWM outputs (DIO.cpp).
- **Commutation:** a GPIO interrupt on any edge of each Hall pin. The handler (IRAM_ATTR, data in
  internal RAM) reads the 3 Halls, looks up a table precomputed per mode and Hall state, and does
  up to 6 GPIO register writes plus `esp_timer_get_time`. Order per step: floating phases lose
  INLx first, then the INHx routes change, then the driven phases get INLx, so every
  intermediate state is Hi-Z or a subset of the target. The duty and mode setters re-read the
  Halls, which recovers a missed edge at standstill.
- **Output gate:** while it is closed (robot disabled, no DS, deadline miss), the motor coasts.
  The gate is applied from SmartIo's 10 ms gate timer and `UpdateOutputGate`.
- **Emergency stop:** `sixstep::OnEmergencyStop` runs first in SmartIo's e-stop handler. It is
  not lock-free like the rest of that handler: it takes the interrupt's spinlock, which every
  holder keeps only for a few register writes. Under that spinlock it coasts every motor and latches a flag, so neither the interrupt nor a
  setter drives a phase again; the generic loop then drives all six pins (and nSLEEP, a DIO
  output) low. Later `OpenSixStep` calls fail and setters are ignored.
- **Close:** the motor coasts (every INHx back on the plain GPIO output), the MCPWM objects are
  deleted, then the output pins are reset with a pull-down (the default pull-up of a reset pin
  would turn the high side on in 3x mode; INHx/INLx also have internal pull-downs, section
  8.3.9.1). After an emergency stop they stay driven low.

## Resource use

| Resource | Use |
|---|---|
| GPIOs | 9 per motor (6 outputs, 3 Hall inputs), plus nSLEEP and nFAULT as DIOs |
| MCPWM | 1 of the 6 timer/operator pairs per motor; the servo PWM outputs share them, so each motor leaves 2 fewer of the 12 servo outputs |
| Interrupts | the GPIO ISR service (shared with Arduino `attachInterrupt`), 3 Hall pins per motor |
| Motors | at most 2 (`kMaxSixStepMotors`) |
| RAM | static, a few hundred bytes per motor slot; no heap after open except the IDF MCPWM objects |
| CPU | one short interrupt per Hall edge: 6 x pole pairs edges per revolution |

## Host simulation

`SixStepSim.cpp` uses DIO sim channels (0-30). A DIO sim value callback on each Hall channel
commutates at once; tests set Halls with `sim::DIOSim::SetValue` and read INLx (enable) and INHx
(high while that phase gets the PWM; the duty is not simulated on the pin). Step times come from
`HAL_GetMonotonicTime`, so `sim::PauseTiming`/`StepTiming` control the speed. It refuses pins that
are allocated DIOs or used by another motor, but does not see other HAL users. There is no
output gate and no emergency stop in the sim. A fresh DIO sim channel reads high, so unset Halls
read 7 and the motor coasts. The sim is single-threaded: a DIO sim callback runs under its value's
lock, so Hall changes from two threads at once (or while another thread opens or closes a motor)
can deadlock.

## Verified and unverified

From the datasheet (SLVSGT3): 3x and 6x truth tables (Tables 8-3, 8-4), MODE decode (Table 8-5)
and latching (8.3.2), PWM up to 200 kHz (1), logic levels, AVDD 3.3 V and tWAKE (7.5),
supply range (7.3), H-variant fault behaviour (8.3.11). From the Boardoza user guide: J3/J4
pinout, jumper functions and defaults.

Unverified:

- Everything on hardware: the whole driver is hardware-unverified.
- The default commutation table (from the Boardoza library) against any real motor; it is
  motor dependent.
- Interrupt latency from Hall edge to phase switch, and behaviour with Hall noise at PWM edges.
- Commutation pauses while the flash cache is disabled (flash writes such as LittleFS logs): the
  ISR service is not IRAM-safe in Arduino-ESP32 3.3.10 (`CONFIG_ARDUINO_ISR_IRAM` off), so Hall
  interrupts wait and the last step stays applied. Installing the service with the IRAM flag
  would crash Arduino `attachInterrupt` handlers during flash writes, so it was not done.
- That the MCPWM group clock accepts the 10 MHz six-step timer next to the 1 MHz servo timers in
  the same group.
- That copying the generator's GPIO-matrix selection to another pin carries the PWM.
- Where the board pulls up the Hall lines, and the VSEN divider ratios (not traced).
